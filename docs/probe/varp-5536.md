- **Encoding:** the value is the **item ID of the elemental rune**, not a bit-packed element + percent.
  `ItemID.FIRERUNE = 554`, `WATERRUNE = 555`, `AIRRUNE = 556`, `EARTHRUNE = 557` (checked with
  `javap -constants` against runelite-api 1.13.1). Air (556) was not observed. **The percent is not in
  this varp.** Water 40% and Water 50% both read 555.
- **No weakness:** `-1`, seen on two separate monsters. After logging in, before any update, the value is also `-1`, so `-1` alone can't tell "no weakness" from "not set yet".
- **When it updates:** when a spell is cast at the monster, **not on a ranged or melee attack**:
  - At tick 1653, 19 ranged hits on a Blue dragon (Water) left the value at `-1`.
  - At tick 405, a Snare on the same dragon set 555, four ticks before the hit landed at 409.
  - Scorpion: targeted at tick 1801, first hitsplat at 1809, value set at 1810.
  - **Not fully consistent:** in a second round (ticks 1894 and 1999), a Hill Giant that was reported as snared and ranged did not update the value. Possibly the Snare didn't fire `[assumed]`; nothing in the log shows the cast.
  - The varp is int-typed: the long array stays 0, and `getVarpLongValue` would throw.
- **Persistence:**
  - Survives region loads (`LOADING` → `LOGGED_IN` kept 557, 0x22a and -1).
  - **Resets on logout.** After `LOGIN_SCREEN` → login it went 0, 0, then -1 (ticks 1987).
  - Persists across target switches. The value stays the last spell target's until another spell writes a different value, so for a monster you have only ranged or meleed it is **stale**.
- **Talk-to:** not observed (not tested).
- **Same-value writes post no event.** A spell on a second Water monster after a Water monster is invisible to `VarbitChanged`.

## Consequences for Task 8 (re-plan)

1. The weakness shown can be **element only**. The percent needs another source. Untested candidate: varp 5537, which carries two unnamed 16-bit varbits (20398 [0..15], 20399 [16..31]) per the Task 1 review.
2. The value describes **the last NPC you cast a spell on**, not the current target. Showing it raw would display stale data for a target you have only ranged or meleed. The spec's staleness rule (addendum item 4) needs a concrete mechanism. One candidate: record the NPC that was targeted when a change event arrived, and show the weakness only for that NPC.
3. Because same-value writes are silent, "no change event" can't be read as "not written".
